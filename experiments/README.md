# FA4 CuTe-DSL vs cuDNN benchmarks (no torch)

Drives the FlashAttention-4 CuTe-DSL SM90 kernels (from `../flash-attention/flash_attn/cute`)
directly from JAX via `cutlass.jax.cutlass_call`. cuDNN baseline is
`jax.nn.dot_product_attention(implementation="cudnn")`. **No torch is installed or used.**

## Setup

```bash
uv sync --group experiments
```

This installs `flash-attn-4` (CuTe kernels, no CUDA build) + `quack-kernels` on
`nvidia-cutlass-dsl[cu13] 4.6.0.dev0`, with `torch` stripped from the resolution and
the jax CUDA-13.3 / cuDNN-9.23 stack pinned (see `pyproject.toml` for why). The
`[cu13]` extra pulls the CUDA-13 build of the DSL codegen backend, so
`cutlass.CUDA_VERSION` is natively `(13, 3)` — the kernels are generated by CUDA-13
tooling. The kernels are made importable without torch by `fa4_loader.py`
(import-time shims only).

## Files

- `fa4_loader.py` — loads the FA4 kernel classes without torch (shim + namespace
  bypass). See module docstring.
- `fa4_jax.py` — `fa4_fwd(q, k, v, scale)`: forward attention via `cutlass_call`;
  `fa4_bwd(q, k, v, out, dout, lse, scale)`: backward (3-kernel pipeline
  preprocess → bwd → postprocess; cross-kernel fp32 `dq_accum` via
  `input_output_aliases`).
- `bench_attention.py` — forward wall-clock benchmark (min/median over windows) FA4 vs cuDNN.
- `bench_backward.py` — backward wall-clock + correctness benchmark FA4 vs cuDNN
  (cuDNN backward = `jax.vjp` of the cuDNN forward). `--nsys-mode fa4|cudnn` runs a
  single impl in a tight loop for nsys.
- `test_bwd.py` — backward correctness check vs cuDNN at two shapes.
- `prof_attn.py` — single-impl runner for profiling. For overhead-free on-device
  kernel time use `nsys` (trace-based); `ncu` over the jax process hangs because it
  intercepts every one of jax's many kernel launches.

## Run

```bash
CUDA_VISIBLE_DEVICES=0 uv run --group experiments python experiments/bench_attention.py   # forward
CUDA_VISIBLE_DEVICES=0 uv run --group experiments python experiments/bench_backward.py     # backward
# on-device kernel times (overhead-free):
CUDA_VISIBLE_DEVICES=0 nsys profile --stats=true -o /tmp/fa4_bwd \
  uv run --group experiments python experiments/bench_backward.py --nsys-mode fa4
```

## Results (1×H200, B=16 S=512 H=20 D=64, bf16, non-causal, forward)

On-device kernel time from `nsys` (overhead-free; each path is a single fused kernel):

| impl            | on-device (nsys) | wall-clock (bench) |
|-----------------|------------------|--------------------|
| cuDNN           | 55.8 µs          | ~65 µs             |
| FA4 (CuTe-DSL)  | 73.5 µs          | ~79 µs             |

cuDNN is ~32% faster on-device for this short-sequence / small-head-dim shape.
FA4 matches cuDNN to ~1 bf16 ULP (max abs diff 4.9e-4). Notes:
- **Warm up ~200 iters before timing** — GPU clock ramp-up otherwise makes early
  wall-clock measurements unreliable (early runs wrongly showed FA4 faster).
- Wall-clock carries ~3.5 µs (FA4) / ~7 µs (cuDNN) of host dispatch overhead vs the
  nsys on-device numbers.

## Results (1×H200, B=16 S=512 H=20 D=64, bf16, non-causal, BACKWARD)

Backward attention FLOPs ≈ 2.5 × forward; forward (non-causal) = 4·B·H·S·S·D, so
bwd ≈ 2.5·4·B·H·S·S·D = **53.7 GFLOP** for this shape.

On-device kernel time from `nsys` (median per-iter, summed across each path's
kernels). cuDNN's `jax.vjp` **recomputes the forward** as part of the backward
(the `flash_fprop` kernel), so we report cuDNN both with and without that
recompute; FA4 receives the precomputed `out`/`lse`.

| impl                                  | on-device (nsys) | wall-clock (min) | TFLOP/s (on-device) |
|---------------------------------------|------------------|------------------|---------------------|
| FA4 bwd (preprocess+bwd+postprocess)  | 171.6 µs         | 180.2 µs         | 312.8               |
| cuDNN bwd (excl. fwd recompute)       | 197.6 µs         | —                | 271.7               |
| cuDNN bwd (incl. fwd recompute, vjp)  | 255.1 µs         | 279.6 µs         | 210.5               |

FA4 backward is ~13% faster on-device (171.6 vs 197.6 µs) excluding cuDNN's fwd
recompute, ~1.49× faster including it; ~1.55× faster wall-clock (the cuDNN vjp
number includes the recomputed forward, as a JAX user would actually pay).

Per-kernel on-device (median): FA4 — bwd_sm90 132.9 µs, preprocess 21.9 µs,
postprocess 16.8 µs. cuDNN — bprop 155.3 µs, fprop(recompute) 57.5 µs,
compute_dot_do_o 22.8 µs, convert_dq_to_16bits 19.5 µs.

**Correctness vs cuDNN backward** (`jax.vjp`), max abs diff / ratio to mean|ref|:

| shape                  | dq             | dk             | dv             |
|------------------------|----------------|----------------|----------------|
| B=2 S=512 H=4 D=64     | 1.2e-4 (2.7%)  | 1.2e-4 (2.7%)  | 2.4e-4 (1.4%)  |
| B=16 S=512 H=20 D=64   | 1.2e-4 (2.7%)  | 1.2e-4 (2.7%)  | 4.9e-4 (2.7%)  |

A few percent relative is expected for bf16 backward (more accumulation than fwd).

### Quack/cutlass version pinning (important for porting to main)

FA4 beta18 (commit 940cd96, 2026-06-19 23:56) matches **quack commit `1fb13ab`**
(2026-06-20 00:21), not PyPI `quack-kernels 0.5.2`. PyPI 0.5.2 was cut from a
*later* commit (256b2e3, 2026-06-20 00:36) that (a) **removed** the
`major_mode_size` arg from `sm90_utils.make_smem_layout` that FA4's backward
passes, and (b) still carries the cutlass-4.5-era dynamic index
`tRS_sC[..., dst_idx]` in `copy_utils.get_smem_store_C`, which cutlass 4.6.0.dev0
rejects (`_check_coord`: "Expected Coord … got (Ellipsis, Int32)"). Commit
`1fb13ab` (the parent of that regression) natively has the 5-arg
`make_smem_layout` and the explicit-`None` `tRS_sC[None,None,None,dst_idx]`, so
**both** skews vanish by pinning to it. `pyproject.toml` does this via
`[tool.uv.sources] quack-kernels = { git = ".../quack.git", rev = "1fb13ab…" }`
(declares version 0.5.0). No quack source-patching needed.

### cutlass 4.6.0.dev0 address-space fix (genuine API drift, in `fa4_loader.py`)

cutlass 4.6.0.dev0 tags `cutlass.jax.cutlass_call` input tensors as `generic`
address space (not `gmem`). The forward TMA path doesn't care, but the backward
loads LSE/dPsum (main bwd) and dQ_accum (postprocess) with `cp.async[.bulk]`
G2S copies whose 4.6 verifier *requires* a `global`/`gmem` source memref. These
buffers are genuinely global device memory, so `fa4_loader._as_gmem_tensor`
re-tags the pointer `gmem` (preserving layout). Applied two places:
- `_patch_quack_bulk_copy_gmem()` wraps `quack.copy_utils.cpasync_bulk_get_copy_fn`
  to re-tag its `src_tensor` (covers LSE/dPsum bulk loads in the main bwd kernel).
- `fa4_jax.launch_post` re-tags `mdQaccum` before the postprocess kernel (its
  dQ_accum cp.async G2S load; the postprocess rebuilds the pointer preserving the
  input's address space, so re-tagging at the boundary propagates through).

Also: the torch import-time shim now reports a PEP 440-parseable
`__version__` (`2.99.0+shim`) and provides `torch.cuda.is_available`, because the
quack git source pulls `torch_c_dlpack_ext`/`tvm_ffi` paths that parse the version
and probe cuda at import (we never call them on the JAX data path).
